## 二、技术栈

### 2.1 核心框架

| 组件 | 选型 | 说明 |
|------|------|------|
| 语言 | Python 3.10+ | |
| Web 框架 | FastAPI | 异步，原生 SSE 支持 |
| ASGI 服务器 | Uvicorn | |
| 进程管理 | Gunicorn | 多 Worker 并发 |
| 反向代理 | Nginx / Tengine | 负载均衡、限流 |

### 2.2 数据层

| 组件 | 选型 | 说明 |
|------|------|------|
| 向量数据库 | Qdrant | Rust 实现，轻量高性能，Docker 一键部署 |
| 缓存/会话 | Redis | 会话存储、缓存、限流计数器 |
| 图片存储 | 阿里云 OSS | 上传后的图片持久化 |

### 2.3 AI 模型层

| 组件 | 选型 | 说明 |
|------|------|------|
| LLM | DeepSeek V4 | OpenAI 标准接口，直接兼容 LangChain |
| 文本 Embedding | BGE-M3 | 北京智源，中文最优 |
| 图文 Embedding | CLIP | 图片 ⇄ 文本对齐 |
| 编排框架 | LangChain | 串联检索 → 生成 |

### 2.4 调用方式

```
后端 ↔ RAG: 进程内调用（Python import）
后端 ↔ LLM: HTTP 调用（OpenAI 标准接口）
后端 ↔ Qdrant: gRPC / HTTP
后端 ↔ Redis: TCP
后端 ↔ OSS: SDK（阿里云 oss2）
```

## 四、核心编排流程（orchestrator.py）

```
客户端 POST /v1/chat
    ↓
① 校验 session_id → 从 Redis 取/建会话历史
    ↓
② 从 OSS 拉图片 → 调 RAG.image_search(image_url)
    │                       └── CLIP → Qdrant 图片向量库 → top-3 candidates
    ↓
③ 调 RAG.text_retrieval(candidates)
    │                       └── BGE → Qdrant 文本知识库 → citations
    ↓
④ 组装 Prompt（候选 + 引用 + 历史 + 问题）
    ↓
⑤ 调 DeepSeek V4 流式生成 → SSE 逐 chunk 推给 Android
    ↓
⑥ 生成完成 → 存回 Redis 会话 → 推 final 事件
```

### 流程中的容错

| 节点 | 失败处理 |
|------|---------|
| Redis 连接失败 | 回退到本地 dict 存储会话（降级不崩溃） |
| OSS 图片拉取失败 | 返回错误 code，不继续后续流程 |
| RAG 搜索返回空 | 直接返回"暂未找到匹配商品"，不走 LLM |
| LLM 调用超时 | 中断流，推 error 事件 |
| 任意节点异常 | 全局异常捕获，返回统一的 JSON 错误 |

```python
# 数据结构
session_key = f"session:{session_id}"

# Redis Hash
{
    "session_id": "uuid",

    "history": [
        {"role": "user", "content": "推荐类似的产品", "image_id": "xxx"},
        {"role": "assistant", "content": "推荐这款...", "candidates": [...]}
    ]

# 过期时间：30 分钟无操作自动清除
# 当 LLM 生成中，标记 session 为 "streaming:true"
# 中断请求时，根据 session_id 取消对应生成任务
```

## 六、Middleware 清单

| 中间件 | 作用 |
|--------|------|
| CORSMiddleware | 放行 Android 跨域 |
| RateLimitMiddleware | 令牌桶限流（Redis + 本地双模式） |
| RequestLogMiddleware | 每个请求记录方法、路径、耗时、状态码 |
| ErrorHandlerMiddleware | 全局异常捕获，返回统一 JSON |
| RequestIDMiddleware | 每个请求注入唯一 trace_id，链路追踪 |

## 七、Runtime 部署架构

```
Nginx (80/443)
  │
  └── upstream backend (Gunicorn + Uvicorn Workers × N)
        │
        ├── Worker 1 (8000)
        ├── Worker 2 (8001)
        └── Worker 3 (8002)

Worker 数 = 2 × CPU 核心数 + 1
```

```
Gunicorn 配置示例：
workers = 4                     # 2*2+1 = 5，保守取 4
worker_class = "uvicorn.workers.UvicornWorker"
timeout = 120                   # 最长等待 120s（LLM 流式场景）
keepalive = 5
max_requests = 1000             # 防止内存泄漏
max_requests_jitter = 200
```
