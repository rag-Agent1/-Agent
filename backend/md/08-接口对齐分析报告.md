# 接口对齐分析报告

> 三方接口对齐检查：Android(laoyuchen) ↔ 后端(你) ↔ RAG(hsh)

---

## 一、整体对齐情况

```
Android App (Kotlin/Retrofit)
    │
    │  POST /api/v1/upload/image
    │  POST /api/v1/chat
    │  GET  /api/v1/chat/stream (SSE)
    │  POST /api/v1/chat/stop
    │  GET  /api/v1/health
    │
    ▼
后端 (你) ← 进程内调用 → RAG 模块 (hsh)
                         ├─ rag/embedding.py
                         ├─ rag/image_search.py
                         ├─ rag/text_retrieval.py
                         ├─ rag/hybrid_search.py
                         └─ rag/db_client.py
```

## 二、接口契约对齐

### 2.1 POST /api/v1/upload/image

| 项目 | Android 发 | 后端需要做的 | 状态 |
|------|-----------|-------------|------|
| Content-Type | `multipart/form-data` | 解析 UploadFile | ✅ 对齐 |
| 字段名 | `file` | 用 `UploadFile(...)` | ✅ 对齐 |
| 大小限制 | ≤10MB | 校验 | ✅ 对齐 |
| 格式 | jpg/png/webp | 校验 | ✅ 对齐 |
| 响应 | 需要 `imageId` 字段 | 返回 `{image_id}` | ✅ 对齐 |

### 2.2 POST /api/v1/chat

| 项目 | Android 发 | 后端需要做的 | 状态 |
|------|-----------|-------------|------|
| 请求字段 | `session_id`, `image_id`, `text` | 用 Pydantic 解析 | ✅ 对齐 |
| 响应字段 | 需要 `sessionId`, `streamUrl`, `messageId` | 返回 `{session_id, stream_url, message_id}` | ✅ 对齐 |

### 2.3 GET /api/v1/chat/stream (SSE)

| 项目 | Android 期待 | ✅/❌ | 说明 |
|------|-------------|-------|------|
| `event: candidates` | `List<Candidate>` | ✅ | 字段名需映射（见下文） |
| `event: delta` | `{"text": "..."}` | ⚠️ **不匹配** | API 文档写的是 `delta_text`，但 Android 代码监听的是 `delta`**
| `event: citations` | `List<Citation>` | ✅ | 字段名需映射（见下文） |
| `event: final` | `FinalEvent` | ✅ | 对齐 |
| `event: error` | `String` | ✅ | 对齐 |

### 2.4 POST /api/v1/chat/stop

| 项目 | Android 发 | 后端需要做的 | 状态 |
|------|-----------|-------------|------|
| 请求 | `{message_id}` | 取消对应 Task | ✅ 对齐 |

## 三、数据模型字段对齐

### 3.1 Candidate 模型 — ⚠️ 关键不匹配

| Android 期待 | API 文档写的 | RAG 返回的 | 后端应该怎么做 |
|-------------|------------|-----------|--------------|
| `sku: String` | `sku_id` | `product_id` | 后端转成 `sku`（**跟 Android 走**） |
| `score: Double` | `score` | `score: float` | 直接传 |
| `title: String` | `title` | `name` | 后端转成 `title` |
| `imageUrl: String` | `image_url` | `image_url` | 传 `image_url` |
| `attrs: Map<String,String>?` | `attrs` | ❌ **不存在** | RAG 没有 `attrs` 字段，后端需要自己构造或从别处补 |
| `price: Double?` | `price` | `price: float` | 直接传 |

### 3.2 Citation 模型 — ⚠️ 关键不匹配

| Android 期待 | API 文档写的 | RAG 返回的 | 后端应该怎么做 |
|-------------|------------|-----------|--------------|
| `sku: String` | `sku_id` | `product_id` | 后端转成 `sku` |
| `id: String` | `chunk_id` | ❌ **不存在** | RAG 没有 chunk_id，后端需要生成 |
| `snippet: String` | `snippet` | `description` | 后端转成 `snippet` |
| `source: String` | `source` | `category` | 后端转成 `source` |

## 四、⚠️ 需要解决的关键问题

### 问题 1：SSE 事件名不统一

```
Android 代码监听:   event: delta
API 文档写的:      event: delta_text
```

**建议：后端按 Android 实际的来，用 `delta`**。API 文档需要更新。

### 问题 2：RAG 的 SearchResult 缺少字段

```python
# RAG 返回的 SearchResult 有:
product_id, name, price, description, category, image_url, score, source

# Android 需要的 Candidate 有:
sku, score, title, imageUrl, attrs, price
```

**缺失映射**：
- `product_id` → `sku`（单纯改字段名 ✅）
- `name` → `title`（单纯改字段名 ✅）
- ❌ **`attrs` 字段 RAG 没有返回** — 需要后端从商品 CSV 或 Qdrant payload 里补，或者跟 hsh 沟通让他在 Qdrant payload 里加上 `attrs`

### 问题 3：RAG 没有专门的 "知识引用检索" 接口

`rag/text_retrieval.py` 的 `search_by_text()` 是文本语义搜索，但流程里需要的是**基于候选 SKU 查知识片段**。目前 RAG 没有提供类似 `retrieve_citations(sku_ids) -> List[Citation]` 的接口。需要跟 hsh 确认或用 SKU ID 过滤 Qdrant。

### 问题 4：Android 的 data/ 包还没写

Android 队友的 `com.agent.android.data.*`（RetrofitClient、ChatRepository、模型类）**一个文件都没创建**。他得补上这些才能联调。

## 五、对齐结论

| 编号 | 问题 | 严重程度 | 需要谁改 |
|------|------|---------|---------|
| 1 | SSE 事件 `delta` vs `delta_text` | 🔴 阻塞 | 改 API 文档为 `delta` 或 告诉 Android 改 |
| 2 | Candidate `attrs` 缺失 | 🟡 中等 | 后端补 / hsh 加 |
| 3 | Citation 字段名不匹配 | 🟡 中等 | 后端做字段映射即可 |
| 4 | RAG 无 `retrieve_citations(sku_ids)` | 🟡 中等 | 跟 hsh 确认接口 |
| 5 | Android data 包不存在 | 🟡 中等 | 通知 laiyuchen 补 |
| 6 | RAG SearchResult 无 `chunk_id` | 🟢 低 | 后端生成 UUID 即可 |
