# 3 人开发手册：Android 拍照识图 + RAG 电商导购 Agent（PoC）

> 本手册用于 3 人小团队协作开发与验收，目标是把项目拆到“能做、能联调、能演示、能评测”。\
> 原始需求与清单请保留参考：[poc\_android\_photo\_search\_agent.md](file:///d:/Trae%20CN%20Work/RAG/poc_android_photo_search_agent.md)（本手册不修改原文档）。

## 0. 交付目标（统一口径）

- **输入**：Android 端拍照/选图 +（可选）用户文本问题
- **输出**：top-k 相似商品候选卡片 + 流式导购回答 + 引用（至少引用候选商品知识片段）
- **安全阈值**：低置信度时必须发起澄清问题，避免“强行给 SKU”
- **范围收缩**：单一品类、200–1000 SKU、单图输入、top-3/top-5、最多 1 轮澄清

## 1. 团队分工与责任边界

### 1.1 Android 工程（Owner：客户端体验）

- 聊天主界面与会话状态管理（消息列表、输入框、发送/重试/中断）
- 图片采集与上传（拍照/相册/压缩/进度/失败提示/权限）
- 流式渲染（SSE 或 WebSocket 二选一，需支持中断）
- 商品候选卡片组件（列表或横滑，点击查看详情）
- 引用展示（展开引用片段与来源）
- 异常兜底（弱网、超时、后端报错、图片不合规）

### 1.2 后端工程（Owner：接口与编排）

- 上传、会话、流式接口（对 Android 提供稳定契约）
- 编排链路：图片检索 → 候选 SKU → 文本检索（候选范围）→ 生成（流式）
- 商品数据服务（SKU 查询、卡片字段组装）
- 观测与日志（检索分数、候选列表、引用、耗时拆分）
- 运行形态（PoC 可单体）：一键启动、最小配置、可演示

### 1.3 RAG/多模态工程（Owner：检索质量与策略）

- SKU 主图 embedding 批处理与入库
- 查询图 embedding + top-k 检索 +（可选）rerank
- 商品知识库切块入库（候选 SKU 范围检索）
- 提示词策略：推荐理由、引用格式、澄清策略
- 评测集与指标（top-1/top-3 命中率、回答可用率、澄清触发率、引用一致性）

## 2. 里程碑与验收（按周交付）

> 以下每周均需提供“可运行的演示路径 + 验收截图/录屏 + 指标或日志样例”。

### Week 1：边界 + 数据 + 最小链路

- 选定**单一品类**与 SKU 清单（200–1000），确定“命中”的判定口径（同款/同系列/同品类）
- 整理商品基础数据（`sku_id/title/attrs/image_url`）与主图文件规范（去重、清晰度筛选）
- Android：会话页骨架 + 拍照/相册入口 + 上传进度/失败重试
- 后端：`/v1/upload/image` 与会话最小实现；能把 `image_id` 串到后续接口
- RAG/多模态：完成 SKU 主图 embedding 批处理 + 入库；提供 `image_id -> top-k candidates` 的最小查询

### Week 2：以图搜图 + 卡片展示 + 基础回答（流式）

- 后端：打通编排 `upload -> image_search -> candidates -> stream`，流式事件至少包含 `candidates` 与 `delta_text`
- Android：上传后先渲染 top-k 候选卡片，再展示流式文本；支持中断与重试
- RAG/多模态：准备商品文本知识（详情/参数/FAQ 至少两类），完成切块入库；生成“推荐理由 + 引用”最小模板
- 验收：3 个固定样例能稳定复现（同一张图多次请求候选基本一致，回答不跑偏）

### Week 3：澄清策略 + 小评测集 + Demo 交付

- 低置信度策略上线（见第 5 节）：触发澄清问题；澄清后重新检索或重排候选
- 建立 20–50 张测试集并产出指标表：top-1/top-3、回答可用率、澄清触发率、引用一致性
- 输出演示材料：架构图/链路图/指标结果/成功与失败样例各 3 条（含归因与对策）
- 最终验收：录屏 3 段（找同款/找替代/不确定澄清）+ 1 页指标表

## 3. 统一数据与接口契约（联调必看）

### 3.1 核心数据结构（建议）

**Candidate（候选商品）**

- `sku_id`：字符串
- `score`：浮点（相似度）
- `title`：字符串
- `image_url`：字符串
- `attrs`：对象（3–5 个关键属性）
- `price`：可选

**Citation（引用）**

- `sku_id`
- `chunk_id`
- `snippet`（引用片段）
- `source`（来源/文档名/section）

**AssistantOutput（助手输出）**

- `delta_text`：流式增量文本
- `candidates[]`：候选数组（可先发送一次）
- `citations[]`：引用数组（可末尾发送）
- `need_clarify`：布尔
- `clarify_question`：字符串（need\_clarify=true 时必填）

### 3.2 API 最小集合（建议）

1. 上传图片

- `POST /v1/upload/image`（multipart）
- 返回：`{ image_id, url }`

1. 发起会话（含图片）

- `POST /v1/chat`
- 入参：`{ session_id, text?, image_id }`
- 返回：`{ message_id, stream_url }`

1. 流式读取回答

- `GET /v1/chat/stream?message_id=...`
- 事件：`delta_text` / `candidates` / `citations` / `final`

> 约定：候选卡片尽量在 stream 早期发出，Android 能先渲染卡片，再补充文字与引用。

## 4. Android 开发检查清单（按功能验收）

- 图片链路
  - 拍照权限与相册权限适配
  - 图片压缩（限制尺寸与大小），上传进度可见
  - 上传失败可重试，失败原因可理解
- 流式体验
  - 消息逐段刷新不卡顿
  - 支持“停止生成”
  - 断线重连或友好提示
- 卡片与引用
  - top-k 卡片稳定渲染（骨架屏/占位）
  - 引用可展开，显示来源与片段
- 可演示性
  - 一键切换测试环境（PoC 服务地址）
  - 录屏不崩溃、不花屏、不会卡死

## 5. 检索与澄清策略（PoC 必须可控）

### 5.1 低置信度判定（建议规则）

- 触发澄清的任一条件即可：
  - `top1_score < T1`
  - `top1_score - top2_score < Tgap`
  - top-k 分数整体偏低或分布过平（说明“不像任何一个”）

> `T1/Tgap` 由评测集调参给出，先用经验值起步，再用 Week 3 数据回归调整。

### 5.2 澄清问题模板（只问 1 个）

- 预算：你大概预算在什么范围？
- 用途：主要用在通勤/运动/办公/送礼哪种场景？
- 关键偏好：你更在意续航/音质/重量/外观哪一点？

### 5.3 生成约束（避免胡说）

- 必须基于候选 SKU 与知识 chunks 输出
- 资料不足时明确说明不确定，并引导澄清
- 推荐理由要“可解释”（绑定 attrs 或知识片段）

## 6. 知识库与数据准备手册（RAG/多模态 Owner）

### 6.1 SKU 图像库规范

- 每个 SKU 至少 1 张主图（建议 2–3 张不同角度，PoC 可先 1 张）
- 统一命名：`{sku_id}.jpg/png`
- 去重与质量筛选：清晰、主体突出、背景干扰少

### 6.2 文本知识来源（至少两类）

- 商品详情/参数（结构化或半结构化）
- FAQ/使用场景/售后规则

### 6.3 切块与元数据（必须）

- `sku_id / section / source / updated_at`
- chunk 内容避免“太长一整页”，优先段落化

## 7. 后端联调手册（接口与可观测性）

### 7.1 编排顺序（建议）

1. `image_id` → 生成查询图 embedding
2. 图像向量库 top-k → `candidates[]`
3. 基于候选 sku\_id 做文本检索 → `citations[]`
4. 组织生成输入 → 流式输出 `delta_text`

### 7.2 日志必打字段（排障用）

- `session_id / message_id`
- `image_id`
- `candidates`（sku\_id + score）
- `citations`（chunk\_id + sku\_id）
- 耗时：embedding / image\_search / text\_search / llm / total
- `need_clarify` 与 `clarify_question`

## 8. 评测与回归（Week 3 必做）

### 8.1 测试集格式（建议表格）

- `test_id`
- `image_path/url`
- `gold_sku_id`（或 gold 系列/品类）
- `notes`（拍摄条件、难点）

### 8.2 指标定义（PoC 够用）

- top-1 命中率：top1 是否命中 gold
- top-3 命中率：top3 是否命中 gold
- 回答可用率：人工 0/1（或 1–5 分）
- 澄清触发率：低置信度样例是否会问
- 引用一致性：回答要点是否能在引用中找到依据

### 8.3 失败样例归因（每条必填）

- 图像质量问题 / 图库覆盖不足 / 检索误召回 / 提示词问题 / 知识缺失
- 对策：补图/补文档/调阈值/改切块/改提示词

## 9. 最终 Demo 验收（答辩/展示清单）

- 录屏 3 段（每段 1–2 分钟）
  - 找同款：拍照 → top-3 → 解释为什么像
  - 找替代：拍照 → 候选 → 按预算/偏好推荐
  - 不确定澄清：低置信度 → 提问 → 再推荐
- 输出 1 页指标表（top-1/top-3、可用率、澄清率）
- 准备 3 条失败样例 + 归因与改进（体现工程闭环）
